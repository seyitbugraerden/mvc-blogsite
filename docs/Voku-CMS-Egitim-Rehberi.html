BÖLÜM 01

Proje ne yapıyor?

Öğrenme hedefi: Siteyi yalnızca görünen ekranlardan değil, verinin kaynağından başlayarak tanımak.

Voku CMS, Voku HTML tasarımını kullanan bir blog ve sayfa yönetim uygulamasıdır. Ziyaretçi yayınlanmış sayfaları okur. Yönetim ekranında aynı içerikler düzenlenir, yeni blog detayları oluşturulur ve taslak/yayın durumu değiştirilir. Sayfa içerikleri SQLite veritabanındaki Pages tablosunda saklanır.

Bu belge, 2688cd4 commitindeki uygulamayı anlatır. Kod örneklerinin bir bölümü okunabilirlik için satırlara ayrılmıştır; sadeleştirilmiş veya öneri niteliğindeki örnekler ayrıca belirtilmiştir. Belge üretimi uygulamanın veritabanını okumaz ve kişisel şifreleri içermez.

Mevcut davranışUygulamadaki karşılığı

Yönetim arayüzü/admin altında içerik listesi ve düzenleme formları
Veri saklamaEF Core aracılığıyla SQLite; varsayılan dosya App_Data/voku.db
İlk içerikler9 sabit sayfa + 4 örnek blog detayı = 13 kayıt

En önemli ayrım: Ekranın tasarımı HTML/CSS ile, o ekrana hangi verinin gideceği C# controller ile, verinin kalıcılığı EF Core + SQLite ile sağlanır.

Admin formları ile ziyaretçi formları aynı amaçta değildir. Admin formunun POST isteği içerik kaydeder. Ziyaretçinin iletişim/bülten formunun gönderimi ise tarayıcıda durdurulur. Bu iki davranış ilerleyen bölümlerde ayrı izlenecektir.

BÖLÜM 06

Program.cs: uygulamanın başlangıç noktası

Öğrenme hedefi: Servis kaydı ile istek işleme hattının farklı görevlerini görmek.

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews(o =>
    o.Filters.Add(new AutoValidateAntiforgeryTokenAttribute()));
builder.Services.AddDbContext<SiteDbContext>(o => o.UseSqlite(...));
// ... cookie, yetkilendirme ve hız sınırı servisleri
var app = builder.Build();
// ... middleware kayıtları
app.MapControllers();
await SeedData.InitializeAsync(app.Services, app.Environment, app.Configuration);
app.Run();

Bu parça sadeleştirilmiştir. builder.Services uygulamanın hangi bileşenleri üretebileceğini bildirir. AddControllersWithViews controller ve Razor desteğini ekler. Global antiforgery filtresi POST gibi güvenli olmayan HTTP yöntemlerinde token doğrulaması sağlar. AddDbContext veritabanı erişiminin nasıl kurulacağını tanımlar.

Dependency injection (DI), controller’ın ihtiyacı olan SiteDbContext’i framework’ün sağlamasıdır. AdminController(SiteDbContext db, IConfiguration configuration) yazınca controller’ın içinde bağlantı açan yeni bir context oluşturmayız. İstek kapsamında verilen context kullanılır. Böylece bağlantı yapılandırması tek yerde tutulur.

Directory.CreateDirectory, App_Data klasörü yoksa oluşturur. Varsayılan veritabanı yolu ContentRootPath’e bağlanır; bu sayede çalışma verisi uygulamanın içerik kökünde tutulur. Bağlantı ayarı verilmişse ?? operatörü varsayılan yerine o değeri seçer.

  1. builder.Build() servis kayıtlarından çalışan uygulama nesnesini oluşturur.
  2. MapControllers(), controller üzerindeki route niteliklerini endpoint olarak kaydeder.
  3. SeedData.InitializeAsync() migrationı uygular ve gerekiyorsa ilk verileri ekler.
  4. app.Run() web sunucusunun istek kabul ettiği çalışmayı başlatır. Seed aşamasında exception olursa Run’a ulaşılamaz.

SeedData içinde CreateScope kullanılmasının nedeni, başlangıç kodunda HTTP isteği olmamasıdır. DbContext scoped bir servistir; seed için açıkça bir scope açılır ve iş bitince kapatılır. await, veritabanı işleminin bitmesini bekler; HTTP sonucu oluşmadan önce gereken verinin hazır olmasını sağlar.

BÖLÜM 09

Doğrulama: formdan gelen veriye güvenmemek

Öğrenme hedefi: Tarayıcı doğrulaması, ModelState ve veritabanı kuralının rolünü izlemek.

[Required, StringLength(120),
 RegularExpression(@"^[a-z0-9]+(?:-[a-z0-9]+)*$",
   ErrorMessage = "Slug küçük harf, rakam ve tire içerebilir.")]
public string Slug { get; set; } = "";

Bu kural ilk-yazim, dotnet-10 ve 2026 değerlerini kabul eder. Boşluk, büyük harf, Türkçe karakter, başta/sonda tire ve art arda iki tire uygun değildir. Uygulama Türkçe başlığı kendiliğinden slug’a dönüştürmez; kullanıcı geçerli slug girmelidir.

KatmanÖrnekNeden tek başına yetmez?
HTMLrequired, maxlength, readonlyTarayıcı dışından istek gönderilerek aşılabilir.
Model doğrulamaRequired, StringLength, RegularExpressionTek kaydı doğrular; diğer kayıtlarla çakışmayı tek başına çözmez.
ControllerAynı tür/slug başka kayıtta var mı?Eşzamanlı istekler arasında yarış olabilir.
VeritabanıUNIQUE(IsDetail, Slug)Son güvence; kullanıcı dostu mesaj için controller kontrolü de gerekir.

MVC, form alanlarını C# nesnesine bağladıktan sonra doğrulama sonuçlarını ModelState içinde tutar. ModelState.IsValid false ise Save, View("Edit", input) döndürür. Böylece kullanıcının girdiği değerler yeniden gösterilir; işlem veritabanına yazılmaz.

Sabit sayfanın slug’ı yalnızca arayüzde readonly değildir. Sunucuda oldSlug != input.Slug kontrolü de yapılır. Bu, HTML özelliğini kaldırıp farklı slug gönderen bir isteğin de reddedilmesini sağlar. Formdaki asp-validation-summary="All" sunucunun eklediği hata mesajlarını gösterir.

Description C# tarafında null olabilir, ancak EF yapılandırması sütunu zorunlu yapar. Save metodundaki input.Description ?? "" boş açıklamayı boş string olarak kaydeder. SQLite için StringLength’i tek başına kesin veritabanı uzunluk engeli saymayın; burada form/model doğrulaması anlamlıdır.

BÖLÜM 10

DbContext ve SQLite

Öğrenme hedefi: C# sorgusunun nasıl tablo verisine dönüştüğünü öğrenmek.

using Microsoft.EntityFrameworkCore;
using Voku.Web.Models;
namespace Voku.Web.Data;
public class SiteDbContext(DbContextOptions<SiteDbContext> options) : DbContext(options)
{
    public DbSet<ContentPage> Pages => Set<ContentPage>();
    public DbSet<AdminUser> AdminUsers => Set<AdminUser>();
    protected override void OnModelCreating(ModelBuilder model)
    {
        model.Entity<ContentPage>().HasIndex(p => new { p.IsDetail, p.Slug }).IsUnique();
        model.Entity<ContentPage>().Property(p => p.Description).IsRequired();
        model.Entity<ContentPage>().Ignore(p => p.Url);
        model.Entity<AdminUser>().HasIndex(p => p.Username).IsUnique();
    }
}

Giriş kontrolü ve mevcut güvenlik davranışı

Öğrenme hedefi: Şimdilik kapalı giriş kontrolünün kodda nasıl korunup ayarlanabildiğini görmek.

options.AddPolicy("AdminAccess", policy =>
    policy.RequireAssertion(context =>
        !builder.Configuration.GetValue("Admin:RequireAuthentication", true)
        || context.User.Identity?.IsAuthenticated == true));

Politikanın mantığı: giriş kontrolü kapalıysa izin ver; açıksa kimliği doğrulanmış kullanıcı iste. AdminController üzerindeki Authorize bu politikayı seçer. Şimdilik appsettings.json false verdiği için /admin ve düzenleme işlemleri anonim erişime açıktır. Bu durum yalnızca login ekranını gizlemek değildir; yetki politikasının izin vermesidir.

  1. Kontrol açıkken GET /admin/login bir LoginModel ile Login.cshtml açar. POST Username ve Password değerlerini modele bağlar.
  2. AdminUsers içinde kullanıcı adı aranır. PasswordHasher saklanan hash ile girilen şifreyi doğrular.
  3. Başarılı girişte kullanıcı adı claim’i olan ClaimsPrincipal kurulur ve SignInAsync oturum cookie’si oluşturur.
  4. Sonraki isteklerde UseAuthentication cookie’den kimliği oluşturur; AdminAccess kontrolü geçilir.
  5. Logout POST isteği SignOutAsync ile cookie oturumunu kapatır. Giriş kapalı modda login action’ı doğrudan /admin’e yönlendirir.

Cookie adı Voku.Admin, HttpOnly ayarı true ve tanımlı bilet süresi dört saattir. Login POST için IP adresi temelinde dakikada 10 istek sınırı vardır; sınır aşılırsa 429 döner. Bu, ayrı bir hesap bazlı kilitleme sistemi değildir. Rol tabanlı çok kullanıcılı yetki modeli de bulunmaz.

Antiforgery/CSRF kontrolü, giriş kapalı olsa bile yazma isteklerinde sürer. Token, formun beklenen istemci akışından geldiğini denetlemeye yardımcı olur; kullanıcı yetkisinin yerine geçmez. Anonim kullanıcı geçerli formu açıp token alabiliyorsa mevcut ayarda düzenleme yapabilir.

CSP inline scriptleri engeller ve kaynakları sınırlar; Html.Raw içeriğini temizleyen bir sanitizer değildir. HTML editörünün güvenilir yöneticiler için tasarlandığını unutmamak gerekir. Yayın ortamında kimlerin düzenleme yapabileceği bu ayara bağlıdır.
